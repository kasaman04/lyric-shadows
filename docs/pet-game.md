# 10属性・10段階の育成
最初の相棒は火・水・草・雷・氷・風・土・毒・光・闇の10体から選ぶ。ホームの育成ボタンまたは #pet から開く。

## 成長とお世話
会話フレーズの「10問チャレンジ」では、既存の場面画像を上に表示し、相手の音声を聞いて返答を3択から選ぶ。初回正解は10コイン、不正解は3コイン減額（残高0が下限）。一度でも間違えた問題は、その後に正解しても加算0。再読み込み後もこの判定を引き継ぐ。間違えた選択肢は再選択できず、正解するまで続ける。正解後は自分の返答と相手の反応を音声で確認し、次へ進む。全639フレーズを対象に、未クリアの問題から10問ずつ出題する（1周の最後は9問）。全問クリア後は次の周で復習できる。進捗は再読み込みや次の相棒にも引き継ぐ。問題・選択肢の順序は開始時に入れ替わる。

100コインで、ごはん・パワー・かしこさのいずれかのお世話を1回できる。間違えずに10問正解すると1回分になる。お世話1回は選んだ数値＋1、成長300秒分。ごはんは既存と同じくおなか全回復・期限72時間へ戻す。お世話画面で「コイン」「聴いた時間」を選べる。コイン払いでは聴いた時間を消費しない。残高と途中の問題は端末ごとの育成データ内に保存し、次のチャレンジ・次の相棒へ引き継ぐ。

問題は `data/conversation-game-questions.json`、場面画像は既存の `public/phrase-images/phrases/`、音声は既存の生成会話から分割した `public/conversation-game-audio/<id>/{prompt,reply,response}.mp3` を使う。ブラウザはサーバーへ選択肢を送信し、サーバーで正誤・残高を確定する。同じ解答の再送と同じお世話の再送は重複加算・消費しない。解答とお世話は共通の保存トランザクションを使い、同時操作でも残高を保つ。

実際に英語を聴いた秒数を残高と日本時間の日別記録へ加算する。再生だけではレベルは上がらない。貯めた時間を、ごはん・パワー・かしこさに使った時だけ成長する。5分・30分・1時間を選べ、5分ごとに選んだ数値が1増える。例えば30分を貯めて5分のお世話を6回するとLv.2になる。ごはんは体格を増やし、おなか100%、期限72時間へ戻す。

| 成長 | 必要なお世話の時間 |
| --- | --- |
| Lv.1 → 2 | 30分 |
| Lv.2 → 3 | 1時間 |
| Lv.3 → 4 | 2時間 |
| Lv.4 → 5 | 3時間 |
| Lv.5 → 6 | 5時間 |
| Lv.6 → 7 | 8時間 |
| Lv.7 → 8 | 12時間 |
| Lv.8 → 9 | 18時間 |
| Lv.9 → 10 | 24時間 |

合計73時間30分。1レベルごとに姿が進化する。属性は引き継ぎ、体格・パワー・かしこさの数値と前の姿から、その個体の新しいデザインを生成する。背景は2レベルごとに荒廃し、Lv.9〜10で廃墟になる。

ごはんをあげないと24時間で空腹、48時間で弱り、72時間で死亡する。閉じている間も進む。死亡した個体は復活せず図鑑へ残る。Lv.10では「旅立ちを見送る」から見送れる。旅立った個体には死亡期限を適用しない。次の相棒は再び10属性から選び、経験値・数値は0、残高・全学習記録・歴代図鑑は引き継ぐ。Lv.10でも旅立つまでお世話できる。

旧100レベルの保存はversion3へ1度だけ移行する。旧経験値の絶対秒数を新しい必要時間へ換算し、過去の姿を legacyForms に保存する。実際に聴いた時間、残高、日別記録は保持する。旧Lv.1の育成中の子は属性を選び直せ、同じ個体の数値と期限を引き継ぐ。

## 画像と28フレーム
初期10体の透過PNGと各28フレームのシートは組み込み画像生成で作成した。
- public/pet-images/starter-{element}-v1.png：図鑑・選択画面の静止画
- public/pet-images/frames-{element}-v1.png：4列×7行、28フレーム
- public/pet-images/motion-manifest.json：シートの寸法と構成
- docs/pet-image-prompts-v3.json：使用した全プロンプト、参照元、コピー先

待機4枚、ごはん6枚、パワー6枚、かしこさ6枚、空腹4枚、弱った状態2枚。public/pet-frames.js がCSS背景の位置を切り替えて再生する。口、手、首、目は実際に異なる画像。ごはんの途中では咀嚼フレームを繰り返す。効果音文字・ハート・電球・地面の揺れは public/pet-reactions.js の演出。OSの視覚効果を減らす設定では普段は静止、ケアは満足した表情を表示する。

選択画面と図鑑は静止画のみで、育成画面にいる現在の1体だけが動きのシートを読み込む。画面を閉じる・図鑑へ移る・進化すると再生タイマー、Image参照、CSS背景を解放する。HTTPキャッシュはブラウザが管理する。

進化後はapp-serverで前の静止画を参照して新しい透過PNGを作り、そのPNGから28フレームを作る。複数レベルを跨いだときは未生成の静止画を古い順に作り、動きは現在の姿だけ生成する。生成中は直前の姿を表示し、失敗後は「もう一度試す」で明示的に再試行する。未生成の昔の姿は記録を開いて生成できるが、昔の動きは再生成しない。

進化のお世話が確定すると、サーバー側で生成を開始して保存する。応答は画像生成を待たずに返すため、生成中も図鑑や学習画面へ移動できる。育成画面を閉じても開始済みの生成は続き、戻ると保存済みの姿を取得する。サーバープロセスを停止した場合は生成も停止するため、再起動後に育成画面から未生成の姿を再開する。

静止画は data/pets/images/<SHA-256>.png に永久保存する。生成した動きは data/pets/images/motion/<petId>/<SHA-256>.png に個体別に保存し、進化・旅立ち・死亡で参照が外れたものだけ削除する。他個体の動きや図鑑の静止画は削除しない。初期10体のシートは共有する静的アセットなので削除しない。

RGBA PNG、実際の透明領域、最大寸法、4列×7行の比率、各セルの可視画素を検証する。AIのポーズ配置が不正確な場合は再生成が必要で、生成途中でも学習・お世話の保存は続けられる。

## 接続・保存
lib/pet-designer.js はCodex標準app-server JSON-RPCと既存ログインを使う。別の画像APIキーは不要。Windowsはインストール先を自動検出し、他環境は CODEX_APP_SERVER_BIN を指定する。PET_AI_ENABLED=false で生成を停止し、公開環境では PET_AI_ENABLED=true が必要。読み取り専用の一時スレッドへ画像と数値を渡し、画像生成以外のツール要求は拒否する。認証トークンを読み取ったりブラウザに渡したりしない。

個体JSONは data/pets/<deviceId>.json に原子的に保存する。端末IDは従来の学習設定と共通。ブラウザのデータ削除で端末IDを失うと、その図鑑へ戻れなくなる。公開環境では画像も残る永続ディスクを PET_DATA_DIR に指定し、未設定では育成APIが503となる。

Supabase保存は data/pet-storage.sql、PET_STORAGE=supabase、SUPABASE_URL、SUPABASE_SERVICE_ROLE_KEY または SUPABASE_SECRET_KEY を使う。JSONと生成PNGを同じプロジェクトへ保存する。画像は非公開の pet-images バケットに保存し、サーバーの画像URLで配信する。Supabase構成ではPET_DATA_DIRの永続ディスクは不要で、ローカルファイルは再取得できるキャッシュ。保存にはrevisionを条件とした比較更新を使い、別プロセスの再生記録・お世話・画像生成結果が重なっても再読込して更新する。

### 無料RenderとPCの画像生成
公開サーバーは PET_STORAGE=supabase、PET_DESIGNER=worker を設定する。公開サーバーではCodexを起動せず、進化時の保存内容を生成待ちの状態として残す。PCの lib/pet-worker.js が15秒ごとに待ち状態を取得し、既存のCodexログインとapp-serverで静止画と28フレームを作り、Supabaseへ保存する。PCが停止してもスマホの学習・お世話・図鑑の保存は続き、待ち状態は残る。PCの処理が再開すると完成画像が公開版に反映される。

PC用のSupabase接続はGit対象外の .env.pet-worker に設定する。公開サーバーと同じ接続先とサーバー専用キーを使う。認証情報はフロントへ渡さない。通常のローカル server.js 起動時に設定ファイルがあればワーカーを背後で起動する。単独で起動するときは scripts/start-pet-worker.ps1 または node lib/pet-worker.js。二重起動はローカルPIDロックで防ぎ、クラウドの生成リースでも別ワーカーとの重複を防ぐ。生成失敗は保存し、画面の「もう一度試す」で明示的に再試行する。

RenderでHTTPSのお世話リクエストを扱うためproductionでは1段のリバースプロキシを信頼する。環境変数にREST APIの末尾 /rest/v1/ が入っていても正規化し、新形式の sb_secret キーはapikeyヘッダーだけに渡す。

再生は実時間を集計し、停止・バッファ待ち・ミュート・シークで飛ばした部分は加算しない。倍速も実時間。重複した区間は1回だけ数える。外部YouTube埋め込みは対象外。未送信区間はIndexedDBへ保存し7日以内を再送する。操作IDでお世話・選択・旅立ちの二重実行を防ぐ。
