# Lyric ShadowsのAI英会話

既存のExpressアプリに `/voice-practice.html` と `/api/voice-practice` を追加しています。Lyric Shadowsのホームにある「AIと話す」から開けます。ホームと同じクリーム色・コーラル色の画面で、育成・聴いた時間の記録へも移動できます。

確認する場合はプロジェクトのフォルダで `npm run voice:dev` を実行します。既定のURLは `http://127.0.0.1:10001/` です。このコマンドも本体サーバーを起動するため、ホームから始めて戻るまで確認できます。画像生成ワーカーの自動起動はこの開発コマンドでは既定で無効です。通常の `npm start` でも同じ機能が利用できます。

## 日本語で場面を決める

ホーム → AIと話す → マイクで日本語の場面説明を録音 → 「話し終えて、設定を確認」 → 設定の確認・修正 → 英会話、の順で進みます。録音だけでは英会話の接続や会話履歴は作りません。

録音はMediaRecorderで最大60秒・8MiBまで。WebM/OpusまたはMP4を使い、サーバー経由でOpenAIの `gpt-transcribe` に日本語の言語ヒント `languages[]=ja` を付けて送信します。録音はファイルとして保存しません。マイクのトラックは録音終了・キャンセル・画面離脱で解放します。文字でも場面を入力・修正できます。

場面説明はResponses APIで相手との関係・場所・時間・相手の名前・会話のきっかけへ整理します。省略された設定を補った項目は「AIが補完」と表示し、ユーザーが編集するとラベルを外します。関係・性別など曖昧な内容を断定しないよう指示します。確認後の設定がRealtimeの人物設定・冒頭の発言・補助候補・保存履歴へ渡ります。相手はMia固定ではありません。

キー未設定や生成失敗時も、文字入力から「自分で設定を入力する」で確認画面を準備できます。この場合のデフォルトは「仮の設定」と表示します。実際の音声入力・AIによる整理・会話接続にはOpenAIキーが必要です。設定の下書きはこのブラウザのlocalStorageに保存します。

## サーバー設定

プロジェクトの `.env` に設定してからサーバーを再起動してください。APIキーはブラウザへ返しません。

```dotenv
OPENAI_API_KEY=your_key_here
ELEVENLABS_API_KEY=your_key_here
# 以下は任意。未設定時の既定値です。
OPENAI_REALTIME_MODEL=gpt-realtime-2.1-mini
OPENAI_TRANSCRIPTION_MODEL=gpt-transcribe
OPENAI_SCENE_TRANSCRIPTION_MODEL=gpt-transcribe
OPENAI_REALTIME_VOICE=marin
OPENAI_HINT_MODEL=gpt-5.6-luna
VOICE_PRACTICE_ELEVEN_MODEL=eleven_v4
# デフォルトは既存voice-catalogのBelleとMark。任意の声IDで上書きできます。
# VOICE_PRACTICE_MIA_VOICE=...
# VOICE_PRACTICE_USER_VOICE=...
# 本番環境では永続ディスク内の絶対パスを指定してください。
# VOICE_PRACTICE_DATA_DIR=/persistent/voice-practice
```

会話はOpenAI RealtimeのWebRTC接続、補助候補と日本語訳はOpenAI Responses API、復習音声はElevenLabsのText to Dialogue with Timestampsで作成します。モデル・声の利用可否は各アカウントの権限と残高に依存します。

## 会話と文法練習

文法練習ではbecause / when / what / if / that / even thoughから選びます。AIがその表現で理由・経験・気持ち・具体例を足しやすい話題を作ります。ユーザーが「Miaに返す」を押すまで自動返答は無効です。発話中の沈黙は会話終了ではありません。

AIの出力バッファが空になり、端末での実際の出力も静かになってから5秒待ちます。ユーザーが話し始めたらヒントのタイマーと古い候補生成を止めます。まだ答えられていないときは、自然な範囲でI / You以外から始まる候補を少なくとも2つ含めるようAIへ指示します。文中のI / Youは禁止しません。That / What / When / 名詞や動名詞など、意味に合う出だしを優先し、単にWellを足すだけの変化は避けます。発話途中で止まった場合は、出だしの変化よりも認識済みの英文へ文法的につながる続きの候補を優先します。候補を選ぶだけでは発言として保存しません。実際に認識された発話だけを保存します。

## 同じ設定でもう一度話す

会話終了後の復習画面・過去の履歴から「同じ設定で、もう一度話す」を押すと、相手・関係・場所・時間・文法モードを引き継いで新しいRealtimeセッションを開きます。前の会話文や録音は新しい会話へ投入しません。元の履歴と音声はそのまま残し、新しい会話は別IDで保存します。これは復習音声のリピートとは別の機能です。旧形式の固定シーンの履歴からも再練習できます。

自由会話ではSemantic VADのlow設定で自動返答します。文法練習の方が、考えながら長く話す時間を確保できます。

## 自然な終了

「会話を終える」または「今日はここまで」「That's all for today」など明確な意思表示で終了を予約します。通常の沈黙や「when …」で止まることは終了条件にしません。自動応答を止め、未完了の文字起こしと現在のAI音声を待ち、実際の会話内容に触れる1〜2文の最後の挨拶を生成します。挨拶が再生し終わってから接続を閉じて保存・復習音声生成へ進みます。

接続障害やページを閉じた場合は、途中の内容をチェックポイントとして保存します。「ここまでを保存して終了」では中断した会話として区別します。接続が切れた場合に自然な挨拶を生成できたかのように扱いません。

## 保存・復習

会話は既定では `data/voice-practice/` にJSONとWAVで保存します。このフォルダはGitの対象外です。`VOICE_PRACTICE_STORAGE=supabase`、または既存の `PET_STORAGE=supabase` がある場合は、既存のサーバー用Supabase接続を使い、専用の非公開 `voice-practice` バケットに保存します。公開Renderではこの方式で再起動・再デプロイ後も履歴と音声を保持します。保存先に接続できなければエラーを表示し、一時ディスクへの保存で代用しません。音声は50MiBまでです。HttpOnly Cookieでブラウザごとに分離し、別のブラウザから会話IDだけで参照することはできません。現段階ではアカウントを使った複数端末間の共有はありません。Cookieを消すと既存の履歴へのアクセスが失われるため注意してください。

復習では二人に別の合成音声を割り当てます。本人の録音や声のクローンではありません。長い会話は1リクエスト1800文字以内に分割し、24kHzのPCMを連結して1本のWAVにします。字幕はElevenLabsが返した時刻と実際の音声の長さから作り、推測の時刻へフォールバックしません。生成済み音声はキャッシュし、再生やリピートで再生成しません。生成中にサーバーが再起動した場合は未完了のジョブを再開します。

再生位置が字幕・自動スクロールを駆動します。翻訳が後から完成しても再生を止めません。全体リピート、発言からの再生、途中からの再開に対応します。

復習音声を実際に再生した時間は、本体と共通の `phraseDeviceId` とPetPlaybackを通じて聴いた時間・育成へ送ります。Realtimeの通話時間全体を学習時間として加算する実装ではありません。

## 確認

`npm run test:voice` でAPIをモックした接続・保存・本人分離・音声生成・同期情報と、実際のフロントエンドのイベント処理を検証します。実APIとマイクでの確認はキー設定後、HTTPSまたはlocalhostで行ってください。

`python scripts/verify-voice-scene-browser.py` は開発サーバー起動後、Chromiumのテスト用マイクとAPIの模擬応答でホーム→実際のMediaRecorder→確認・修正→会話開始→再練習→ホームへの帰還を確認します。ユーザーのマイクや保存済み育成データは使いません。`python scripts/verify-voice-practice-browser.py` は生成済みの短いサンプルWAVを使い、字幕・連続再生・リピートを確認します。

本番に公開する前にはアプリ全体のログイン認証、永続ディスク、HTTPS、使用量制限を運用環境に合わせて設定してください。ここでのブラウザ所有Cookieと件数制限はアカウント認証を置き換えるものではありません。
